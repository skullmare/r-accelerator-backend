# Настройка агента

Агент — это один этап маршрута. У него девять полей, из них четыре
обязательных. Всё поведение задаётся двумя промптами: никаких флагов,
температур и схем артефакта больше нет.

API: `GET/POST/PATCH /api/v1/accelerator/admin/agents` — только с правом
`accelerator_agents.manage` (или superadmin).

---

## Поля

| Поле | Тип | Обязательно | Зачем |
|---|---|---|---|
| `systemPrompt` | string ≤ 20000 | **да** | Основная инструкция агента |
| `completionPrompt` | string ≤ 5000 | **да** | Условие завершения этапа, обычным текстом |
| `name` | string ≤ 150 | **да** | Имя агента в интерфейсе |
| `order` | number | **да** | Место в маршруте |
| `knowledgeIds` | ObjectId[] | нет | Базы знаний, закреплённые за агентом |
| `description` | string ≤ 1000 | нет | Описание специализации в интерфейсе |
| `avatarUrl` | URL ≤ 2000 | нет | Аватарка |
| `thinkingAvatarUrl` | URL ≤ 2000 | нет | Аватарка состояния «агент думает» |
| `nextAgentId` | ObjectId | нет | Переопределение перехода для нелинейного маршрута |

Больше у агента настроек нет — модель, температура, лимиты токенов, глубина
поиска по контексту одинаковы для всего сервиса и задаются в
`config/accelerator.config.js`.

### Минимальный работающий агент

```json
{
  "name": "Роман",
  "order": 1,
  "systemPrompt": "Ты Роман, эксперт по рынку и нише...",
  "completionPrompt": "Этап завершён, когда понятны рынок, ниша и конкуренты."
}
```

Этого достаточно, чтобы агент гарантированно провёл этап и передал проект
дальше.

---

## Как писать `systemPrompt`

Это инструкция роли — она уходит в модель на каждом ходу. Хороший промпт
отвечает на три вопроса:

1. **Кто агент и чем занимается.**
   «Ты Роман, эксперт по рынку и нише для стартап-акселератора.»
2. **Что он должен выяснить у пользователя.** Перечислите темы прозой — это и
   есть замена прежним `requiredFields`.
   «Помоги основателю описать рынок, сформулировать гипотезу ниши, выявить
   конкурентов и ключевые риски.»
3. **Как вести разговор.**
   «Задавай вопросы по одному. Уточняй расплывчатые ответы. Если человек
   затрудняется — предложи варианты.»

Полезно прямо назвать ключи, под которыми сохранять данные, — тогда карточка
этапа получается предсказуемой:

> «Всё существенное, что узнал, сразу сохраняй инструментом `save_data` — под
> ключами `market`, `niche`, `competitors`, `risks`.»

Это не обязательно (агент придумает ключи сам), но упрощает отладку и делает
итоговые документы однообразными.

**Чего в промпте быть не должно:** описания формата итогового документа —
документ пишется отдельным вызовом со своей инструкцией; попыток заставить
агента самому «переводить пользователя на следующий этап» — этап завершает
пользователь кнопкой.

## Как писать `completionPrompt`

Это условие, по которому агент решает, что данных достаточно. Обычный текст,
не схема и не JSON.

**Хорошо** — проверяемый список тем:

> «Этап завершён, когда понятно: какой это рынок, в чём гипотеза ниши, кто
> основные конкуренты и какие риски у затеи. Формулировки могут быть
> черновыми — важно, чтобы по каждому пункту был осмысленный ответ
> пользователя, а не догадка.»

**Плохо** — недостижимое условие:

> «Этап завершён, когда собран полный конкурентный анализ с долями рынка,
> выручкой каждого конкурента и подтверждёнными источниками.»

Такой этап пользователь не закроет никогда: агент будет бесконечно
переспрашивать. Условие завершения должно быть выполнимо в разговоре на
10–15 реплик.

Отдельно стоит разрешить агенту довольствоваться черновыми ответами — это
главный практический способ избежать зацикливания.

## Знания (`knowledgeIds`)

Базы знаний заводятся отдельно (`/api/v1/accelerator/admin/knowledge`) и
привязываются к агенту списком `_id`. Поиск идёт только по привязанным базам:
пустой список — агент работает без знаний. Найденные фрагменты приходят
агенту как справочный материал, а не как инструкции.

## Маршрут

Маршрут пользователя — агенты, отсортированные по `order`. Переход после
этапа: `nextAgentId`, если он задан и агент существует, иначе — следующий по
`order`.

Практический вывод: **для обычного линейного маршрута `nextAgentId` не нужен
вообще**. Достаточно проставить агентам `order` 1, 2, 3… Заполнять
`nextAgentId` имеет смысл, только если маршрут нелинейный.

**`order` должен быть уникальным.** Переход ищет агента со строго большим
`order`, поэтому при одинаковых значениях один из агентов будет пропущен.
Сервер это не проверяет — следите сами.

Ограничения, которые проверяет сервер:

- `nextAgentId` должен ссылаться на существующего агента (иначе `400`);
- агент не может ссылаться сам на себя (`400 NEXT_AGENT_SELF_REFERENCE`) —
  это был бы вечный цикл этапа.

Последний агент маршрута — тот, после которого нет ни `nextAgentId`, ни агента
с большим `order`. После его этапа проект получает `status: "completed"`.

## Чек-лист перед запуском агента

- [ ] `systemPrompt` описывает роль, темы для выяснения и манеру разговора;
- [ ] `completionPrompt` перечисляет, что должно быть выяснено, и достижим в
      коротком диалоге;
- [ ] `order` не конфликтует с другими агентами (порядок определяет маршрут);
- [ ] `name` заполнено — оно попадает в заголовок документа этапа;
- [ ] `description` заполнено, если нужен подзаголовок в PDF и в карточке
      агента на фронте;
- [ ] `knowledgeIds` указаны, если агент должен опираться на методички;
- [ ] проверено вживую: пройдите этап сами и убедитесь, что агент вызвал
      `stage_ready` (в ответе `POST .../messages` придёт
      `readyForArtifact: true`).

## Отладка: агент не завершает этап

Сессия хранит всё, что нужно для разбора — `GET .../expert-sessions/:id/messages`
возвращает `collectedData` и `readyForArtifact`.

| Симптом | Причина | Что делать |
|---|---|---|
| `collectedData` пустой | Агент не вызывает `save_data` | Добавить в `systemPrompt` явную инструкцию сохранять данные сразу, в том же ходу |
| Данные собраны, `readyForArtifact: false` | Условие завершения слишком строгое | Смягчить `completionPrompt`, разрешить черновые формулировки |
| Агент прощается, хотя этап не готов | Противоречие между `systemPrompt` и `completionPrompt` | Убрать из `systemPrompt` фразы про переход к следующему этапу |
| Агент задаёт вопросы, на которые уже отвечали | Диалог длиннее 30 сообщений (глубина истории) | Условие завершения слишком объёмное — разбить этап на двух агентов |
